Task: knowledge
User: How does `ByteTokenizer` encode and decode text?
Chit: `ByteTokenizer` (`byte-utf8`) maps every UTF-8 byte directly to an integer token ID in `0..255`, giving a fixed vocabulary size of 256 without an external vocabulary file.

Task: knowledge
User: Why does `ByteTokenizer.encode` use `errors="surrogatepass"`?
Chit: It prevents lone surrogates from malformed JSON input from crashing UTF-8 encoding, allowing `decode` to replace invalid byte sequences safely.

Task: knowledge
User: What optional second tokenizer does Chit support besides `byte-utf8`?
Chit: Chit supports `BpeTokenizer` (`bpe-tokenizers-json-v1`), which loads a Hugging Face `tokenizer.json` asset and verifies its SHA-256 hash on checkpoint load.

Task: knowledge
User: What happens if a checkpoint's tokenizer name or SHA-256 hash does not match during fine-tuning or runtime loading?
Chit: Both `train()` and `ChitRuntime.from_checkpoint()` raise a `ValueError` to prevent silent token-ID mismatches.

Task: knowledge
User: What neural architecture does `ChitModel` implement in `model.py`?
Chit: `ChitModel` is a pre-LayerNorm decoder-only Transformer with `CausalSelfAttention`, a 4x-expanded GELU MLP in each `Block`, a final `LayerNorm`, and weight tying between `token_embedding` and `lm_head`.

Task: knowledge
User: How are weights initialized in `ChitModel._init_weights`?
Chit: Linear and Embedding weights are initialized from a normal distribution with mean `0.0` and standard deviation `0.02`, and Linear biases are initialized to zero.

Task: knowledge
User: Why does `ChitModel` tie `lm_head.weight` to `token_embedding.weight`?
Chit: Weight tying shares the embedding matrix between input tokens and output logits, reducing parameter count and improving sample efficiency for a compact model.

Task: knowledge
User: Which positional encoding modes are supported by `ChitModel` and `ModelConfig`?
Chit: They support learned `absolute` positional embeddings (`nn.Embedding(block_size, n_embd)`) and `rope` (Rotary Position Embeddings) parameterized by `rope_theta`.

Task: knowledge
User: What constraint does `CausalSelfAttention` enforce when `position_encoding` is set to `"rope"`?
Chit: It requires `n_embd` to be divisible by `n_head` and the attention head dimension (`n_embd // n_head`) to be an even integer.

Task: knowledge
User: How does `CausalSelfAttention` compute attention in PyTorch?
Chit: It uses `F.scaled_dot_product_attention`, applying causal masking when `past_length == 0` and `t > 1`, or an explicit boolean lower-triangular mask when extending a non-empty KV cache with multiple tokens.

Task: knowledge
User: Why does `model.py` define `_LEGACY_BUFFER_SUFFIXES = (".attn.mask",)`?
Chit: Older checkpoints saved a causal mask buffer before switching to `scaled_dot_product_attention`; `clean_state_dict()` strips `.attn.mask` so legacy checkpoints load cleanly with `strict=True`.

Task: knowledge
User: How does `ChitModel.generate()` use KV caching during autoregressive decoding?
Chit: When `use_cache=True`, it prefills `kv_caches` over the prompt window once and then passes only the newest token `idx[:, -1:]` with `past_length` on subsequent steps until `block_size` is reached.

Task: knowledge
User: How does `ChitModel.generate()` handle `temperature <= 0`?
Chit: When `temperature <= 0`, `generate()` performs deterministic greedy decoding by selecting `sampling_logits.argmax(dim=-1, keepdim=True)`.

Task: knowledge
User: How does repetition penalty work in `ChitModel.generate()`?
Chit: When `repetition_penalty > 1.0`, it penalizes only newly generated tokens after `prompt_len` (`idx[b, prompt_len:]`) by dividing positive logits and multiplying negative logits by `repetition_penalty`.

Task: knowledge
User: Does calling `ChitModel.generate()` mid-training leave the model in eval mode?
Chit: No. `generate()` saves `was_training = self.training`, switches to `self.eval()` inside a `try` block, and restores `self.train(was_training)` in the `finally` block.

Task: knowledge
User: How does `ChitModel.generate()` compute the returned confidence score when `return_details=True`?
Chit: It gathers the log-probability of each sampled token from unpenalized `log_softmax` logits, averages the sequence log-probabilities, exponentiates them, and clamps the result to `[0.0, 1.0]`.

Task: knowledge
User: How does `TextDataset` in `data.py` store a byte-tokenized corpus in memory?
Chit: For `byte-utf8`, `TextDataset` reads the file incrementally in 1 MB chunks into a `bytearray` and wraps it with `torch.frombuffer(..., dtype=torch.uint8)` so each token uses one byte of host RAM.

Task: knowledge
User: How does `_find_record_starts` identify training record boundaries in `data.py`?
Chit: It scans the raw UTF-8 byte buffer for `b"Task: "` at byte 0 and every occurrence of `b"\nTask: "`, storing the starting byte offsets in `ds.record_starts`.

Task: knowledge
User: How does `_sample_starts` choose training windows when `record_starts` are present?
Chit: It samples 70% of batch windows aligned directly to `Task: ` record starts and 30% uniformly across all valid byte offsets so the model learns both prompt beginnings and mid-record continuations.

Task: knowledge
User: What does `_apply_answer_loss_mask` do during batch sampling in `data.py`?
Chit: For byte-tokenized datasets, it masks prompt target tokens up to the first `\nChit: `, `\nReasoning: `, or `Task: prose\n` header with `-100` so cross-entropy loss trains on answer and reasoning tokens.

Task: knowledge
User: Why does `_apply_answer_loss_mask` check `min_remaining` before masking a row?
Chit: It ensures at least 16 unmasked target tokens remain when `width >= 128` (or 1 when smaller), preventing rows with long prompts from having almost every token masked out.

Task: knowledge
User: What happens in `ChitModel.forward()` if every target token in a batch is `-100`?
Chit: If no target token differs from `-100`, `forward()` returns `logits.sum() * 0.0` instead of `NaN` from `F.cross_entropy`.

Task: knowledge
User: How does `random_mixed_batch` combine multiple corpus files during training?
Chit: It samples a source dataset per sequence using `torch.multinomial` over the configured source weights, then draws a window within that file so windows never cross unrelated file boundaries.

Chit: `train()` uses `torch.optim.AdamW` with configured `learning_rate` and `weight_decay`, and clips gradient norms each step with `torch.nn.utils.clip_grad_norm_(m.parameters(), t.grad_clip)`.
